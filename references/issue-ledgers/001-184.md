# KernelSU closed-issue learning ledger (rows 1–184)

Source: `ksu-research/closed-issues.jsonl`, lines 1–184. Each record reads the issue question, state reason, linked closing PRs, and the available discussion rather than treating its GitHub state as proof.

**Evidence rule.** `COMPLETED` only establishes that the issue was closed. Where neither a maintainer fix nor a reporter verification appears in the captured issue, this ledger says **未证实关闭** (closure not evidenced); it does not infer that a feature works. “Module lesson” means a constraint or practice reusable when writing a KernelSU module, not a promise that KernelSU supplies the requested feature.

## 001–062

### #1 — Supporting x86/x86_64

- **问了什么：** BlissOS 维护者询问 KernelSU 是否计划支持 x86/x86_64，并愿意测试。
- **怎么解决／为何关闭：** 讨论给出签名尺寸/哈希、KPROBES 和 `THREAD_INFO` 等适配方向；贡献者后来报告已能编译并工作。后续另一次 bootloop 没有结论，故不能把一次成功推广为所有 x86 设备均兼容。
- **可复用模块开发教训：** 架构移植与模块兼容必须逐项核验 kernel config、符号、ABI 和真实冷启动，不能只凭一次编译成功下结论。

### #8 — TIF_SECCOMP removed from x86 thread_info.h

- **问了什么：** x86 新内核移除了 `TIF_SECCOMP`，导致集成代码不匹配。
- **怎么解决／为何关闭：** 维护者确认 5.11+、`CONFIG_GENERIC_ENTRY` 环境应改用 `syscall_work`；讨论明确称已修复。
- **可复用模块开发教训：** 对内核接口采用 feature/config 条件编译，不要把旧符号存在当作恒定前提。

### #15 — No working initrd-magisk

- **可复用模块开发教训：** 不可假设 Magisk 生态的脚本、目录或 daemon 行为会在 KernelSU 下兼容。
