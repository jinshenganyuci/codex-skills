# 熊大静态分析报告模板

按用户问题删减不相关章节，但不要省略样本身份、安全边界、证据等级和高危分支。

## 直接结论

先用一至三句话回答用户最关心的内容：

- 内置控制地址或当前下载地址；
- 熊大配置应放置的准确目录；
- 新版本新增或删除了哪些目录和文件。

示例：

```text
本次版本确认的配置目录为 <从当前样本证明的路径>。
本次上传文件真实类型为 <当前检测结果>。分析全程未执行样本。
```

## 只读取或只修改

### 只读取

列出有 `r/rb/O_RDONLY`、输入流、`stat/access` 或资源加载证据的路径。明确这些不是样本主动创建。

### 修改已有节点

把 `/proc`、`/sys`、cgroup、设备节点、权限和 bind mount 操作单独列出。不要把写入虚拟控制节点说成创建普通文件。

### 删除目标

列出 `unlink/remove/rmdir/rm` 目标及触发条件。

### 未解决候选

只列对用户有价值的候选，说明为什么尚未确认。不要用原始字符串列表淹没结论。

## 高危行为

用醒目短句列出删除根目录、设备节点、重启、格式化、权限持久化或隐蔽挂载等行为。

必须同时说明：

- 命令或 API；
- 所在组件；
- 调用条件和可达性证据；
- 是否属于正常路径、功能按钮或异常分支；
- 静态分析不能证明的部分。

不要因为分支可达性未完全证明就省略危险字符串，也不要把条件分支说成必然执行。

## 方法与限制

结尾固定覆盖：

- 全程是否执行样本；
- 成功扫描的层级：APK 成员、DEX、外层 ELF、Zstd、重建映像、内嵌 ELF、内嵌 Shell；
- 哪些结论有调用点证明，哪些只是候选；
- 加壳、间接调用、动态拼接或运行环境造成的盲区；
- 卡密、令牌等敏感内容是否已隐藏。

建议结尾：

```text
以上来自只读静态分析，样本及内嵌脚本均未执行。路径字符串只有在写入调用得到确认后才归入创建清单；未解决项目已单独标注。
```
